# Crypto Price Service

Небольшой backend-сервис, который раз в минуту получает индексные цены BTC/USD и ETH/USD с публичного API Deribit, сохраняет историю в PostgreSQL и предоставляет данные через REST API.

Проект запускается через Docker Compose. Устанавливать Python, PostgreSQL или Redis на компьютер отдельно не нужно — они работают в контейнерах.

## Что умеет сервис

- Получает индексы `btc_usd` и `eth_usd` с Deribit.
- Автоматически запускает сбор раз в 60 секунд.
- Сохраняет цены и UNIX timestamp в PostgreSQL.
- Отдаёт историю, последнюю цену и историю за выбранный период.
- Ограничивает размер ответа пагинацией.
- Не сохраняет повторную запись для одного тикера и того же timestamp.
- Предоставляет health check для проверки доступности базы данных.

## Технологии

- **Python 3.11+** — язык проекта.
- **FastAPI** — REST API и Swagger-документация.
- **SQLAlchemy 2** — работа с базой данных через ORM.
- **PostgreSQL** — хранение истории цен.
- **aiohttp** — асинхронные запросы к Deribit.
- **Celery Worker** — выполнение фоновой задачи сбора цен.
- **Celery Beat** — запуск задачи по расписанию.
- **Redis** — брокер сообщений и backend результатов Celery.
- **Docker Compose** — запуск всех сервисов одной командой.
- **pytest** — автоматические тесты.

## Что нужно установить

Установите и запустите **Docker Desktop** (Windows/macOS) или **Docker Engine с Compose plugin** (Linux).

Проверить установку можно командами:

```bash
docker --version
docker compose version
```

## Запуск проекта

### 1. Скачайте проект

Склонируйте репозиторий или скачайте ZIP с GitHub и распакуйте его. Все команды ниже нужно выполнять из корневой папки проекта — там, где находится `docker-compose.yml`.

### 2. Создайте файл настроек `.env`

Скопируйте пример конфигурации в локальный файл `.env`.

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**macOS / Linux / Git Bash:**

```bash
cp .env.example .env
```

Для стандартного локального запуска значения из примера подходят. Файл `.env` содержит локальные настройки и не должен попадать в Git; `.env.example` хранится в репозитории как шаблон.

### 3. Соберите и запустите контейнеры

Убедитесь, что Docker запущен, затем выполните:

```bash
docker compose up --build -d
```

### 4. Убедитесь, что сервисы запущены

```bash
docker compose ps
```

Посмотреть логи API, сборщика и планировщика:

```bash
docker compose logs -f api worker beat
```


### 5. Откройте API

- **Swagger UI:** <http://localhost:8000/docs> — здесь можно выбирать endpoint, вводить параметры и нажимать **Execute**.
- **Проверка API и базы данных:** <http://localhost:8000/health>.

Первая цена появится после первого успешного запуска фоновой задачи. Beat запускает сбор по расписанию, поэтому после старта контейнеров может понадобиться подождать около минуты.

## API endpoints

Во всех запросах к ценам параметр `ticker` обязателен. Поддерживаются только `btc_usd` и `eth_usd`. Неподдерживаемый тикер или некорректные параметры приводят к ответу `422`.

### Получить историю цен

```http
GET /api/prices?ticker=btc_usd&limit=100&offset=0
```


Например, чтобы получить следующую страницу по 100 записей, используйте `offset=100`:

```http
GET /api/prices?ticker=btc_usd&limit=100&offset=100
```

Записи возвращаются от старых к новым. Для больших объёмов истории используйте `limit` и `offset`, а не загружайте всю историю одним запросом.

### Получить последнюю цену

```http
GET /api/prices/latest?ticker=eth_usd
```

Возвращает одну последнюю сохранённую запись. Если записей для тикера пока нет, API отвечает `404`.

### Получить цены за период

```http
GET /api/prices/filter?ticker=btc_usd&date_from=2026-10-01T00:00:00Z&date_to=2026-10-14T00:00:00Z
```


### Проверить состояние сервиса

```http
GET /health
```

Проверяет соединение с PostgreSQL. При недоступной базе возвращается `503`.

## Как работает сбор цен

1. Celery Beat ставит задачу `collect_prices` в очередь раз в 60 секунд.
2. Celery Worker запрашивает индексные цены `btc_usd` и `eth_usd` у Deribit.
3. Успешно полученные данные сохраняются в PostgreSQL.
4. Если запрос для одного тикера завершился ошибкой, сервис записывает её в лог и продолжает обработку второго тикера.
5. У задачи в расписании есть срок действия (`expires`). Если worker долго не работает, устаревшая задача не должна запускать много запоздалых сборов после восстановления.

В таблице действует уникальное ограничение на пару `(ticker, timestamp)`. Оно не позволяет сохранить две записи одного тикера с одинаковым timestamp. Если такая запись уже существует, повторное сохранение пропускается.


## Запуск тестов

Тесты используют SQLite в памяти и моки, поэтому для них не требуются работающие PostgreSQL, Redis или доступ к Deribit. Нужен Python 3.11 или новее.

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его.

**Windows PowerShell:**

```powershell
.venv\Scripts\Activate.ps1
```

**macOS / Linux:**

```bash
source .venv/bin/activate
```

Установите проект с зависимостями для разработки и запустите тесты:

```bash
python -m pip install -e ".[dev]"
pytest -q
```
